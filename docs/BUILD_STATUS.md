## Waiting on the database

These items are left on purpose. They need the CanDo database password or a live database connection.

- The migration files are not pushed to the CanDo Supabase project.
- Hyperdrive is not created. The secret name for that password is `SUPABASE_DB_PASSWORD`.
- The hourly seal, the daily digest, and the event sender do not query Postgres yet. The tests use an in-memory store. When Hyperdrive is created, query caching must be off.
- Email sign-in and the return addresses are still switched on in the Supabase dashboard. See `docs/SETUP.md`.
- Core HR (people, jobs, positions, org units, agreements, and the hire flow) is tested in memory. Those rows are not in the CanDo database. The site shows sample people and positions.
- The org chart reads those same in-memory records. It does not query Postgres, and open charts hear about a change only inside this process.
- Rule files and agreement versions are loaded in memory. They are not written to `ref.rule_edition` or the agreement tables. Comparing two rule sets lists what changed. It does not run a pay simulation. That waits for the payroll steps.
- Creating a sign-in account at the lead time after a hire is tested with an in-memory stand-in. It does not call a customer's directory.
- Ending one job while another continues does not yet settle leave, benefits, dues, or records of employment. Those belong to later steps.
- Date of birth stays out of this slice. The sensitive-data table is not in the CanDo database yet. SIN masking is tested in memory.
- This login could not confirm whether `SUPABASE_DB_PASSWORD` is available to GitHub Actions, so nothing was pushed to the CanDo database and Hyperdrive was not created.
