## Waiting on a live connection

The tables are on the CanDo project. These items still do not use that database.

- Hyperdrive is not created. `SUPABASE_DB_PASSWORD` works. The latest try (GitHub Actions run 41346287117) was refused with HTTP 400, code 9106. The saved `CLOUDFLARE_API_TOKEN` is only 20 characters, so it is not a full Cloudflare API token. The site config has no database binding. When Hyperdrive is created, query caching must be off.
- The hourly seal, the daily digest, and the event sender do not query Postgres yet. The tests use an in-memory store.
- Email sign-in and the return addresses still have to be switched on in the Supabase dashboard. See `docs/SETUP.md`.
- Core HR (people, jobs, positions, org units, agreements, and the hire flow) is tested in memory. The tables exist and are empty. The site shows sample people and positions.
- The org chart reads those same in-memory records. It does not query Postgres, and open charts hear about a change only inside this process.
- Rule files and agreement versions are loaded in memory. They are not written to `ref.rule_edition` or the agreement tables. Comparing two rule sets lists what changed. It does not run a pay simulation.
- Pay-run rules are tested in the `@candohr/pay-runs` package. The claim test uses the throwaway database in GitHub Actions. The live site still has no Hyperdrive connection, so it does not open a pay run or write results. The payroll tables exist and are empty. A Cloudflare Workflow and a queue consumer are not attached yet.
- Creating a sign-in account at the lead time after a hire is tested with an in-memory stand-in. It does not call a customer's directory.
- Ending one job while another continues does not yet settle leave, benefits, dues, or records of employment. Those belong to later steps.
- Date of birth stays out of this slice. SIN masking is tested in memory.
